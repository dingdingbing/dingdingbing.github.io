# 自我介绍里的面试钩子设计

自我介绍不是把简历从头念一遍，而是用 1 分钟左右把面试官引到自己最有准备、最能体现价值的项目上。

我之前自我介绍容易偏“经历罗列”：公司、技术栈、做过哪些模块都说了，但没有明确告诉面试官“你可以从这里继续问”。这样面试官可能随机挑问题，也可能顺着简历上不够熟的点追问。

更好的方式是：自我介绍里主动埋 1 到 2 个钩子，让面试官自然追问到准备最充分的项目。

## 什么是面试钩子？

面试钩子就是一句能引出追问的信息。

它不是空泛形容词，例如：

```text
我参与过复杂业务系统建设。
```

这句话太大，面试官不知道该问哪里。

更好的钩子应该包含：

- 业务场景：解决什么业务问题。
- 个人职责：我负责哪一块。
- 技术设计：用了什么设计或机制。
- 可追问点：表结构、消息、事务、性能、数据一致性。
- 结果：上线效果或量化结果。

例如：

```text
在多主体互转项目里，我负责履约板块，通过关系表建模、消息顺序执行和回调主流程复用原履约能力，把原来只支持钢银平台内部交易的链路扩展到多个关联主体之间流转。
```

这句话里有几个明显追问点：

- 多主体互转是什么业务？
- 关系表怎么设计？
- 为什么要用消息？
- 单队列单消费者怎么保证顺序？
- 回调主流程怎么复用原有履约能力？
- 头节点、中间节点、尾节点怎么判断？
- 怎么保证提货申请和实提数据一致？

这就是钩子的价值。

## 自我介绍应该怎么组织？

推荐顺序：

```text
我是谁
当前公司和业务规模
我负责的核心链路
重点项目钩子
工程能力补充
求职方向
```

不要在自我介绍里展开所有项目。自我介绍只负责“开门”，项目细节留给面试官追问。

## 1 分钟版本

```text
面试官您好，我叫丁富兵，目前有 6 年 Java 后端开发经验，现在就职于上海钢银电子商务股份有限公司，主要负责钢银电商交易平台相关的后端研发工作。

钢银电商是上海钢联旗下的钢铁产业互联网平台，服务钢厂、钢贸商、终端采购方以及仓储物流等产业链角色。我这几年主要参与的是交易履约、提货申请、采购/销售实提、合同结算、库存协同等核心业务链路，比较熟悉 B2B 电商中订单、履约、库存、结算之间的复杂状态流转。

项目上，我最近参与了多主体互转流程改造，主要负责履约板块，包括提货申请、实提、出库凭证、收货、结算等流程。这个项目把原来只支持钢银平台内部交易的链路，扩展到钢银和子公司、关联公司之间的主体互转。我参与了关系表和关系明细表设计，通过消息通信和回调主流程接口的方式复用原有履约能力，避免重复开发，同时通过头节点、中间节点、尾节点区分不同订单在链路中的处理逻辑。

另外我也做过提货履约与实提链路通用化改造，处理过寄售转寄售、多次转卖场景下采购实提、销售实提不一致和漏生成的问题。工程能力方面，我做过合同批量打印性能优化、资源池入库去重、慢 SQL 调优、生产 OOM 排查和财务一致性问题处理，对 MySQL、事务、MVCC、线程池、CompletableFuture、线上问题定位这些方面都有实际经验。

我现在希望继续找 Java 后端方向的岗位，比较希望参与复杂业务系统、交易履约、数据一致性或者高稳定性要求比较高的后端系统建设。
```

## 30 秒版本

```text
面试官您好，我叫丁富兵，有 6 年 Java 后端开发经验，目前在上海钢银电商做交易平台相关研发。我的工作主要围绕 B2B 钢铁电商的核心交易履约链路，包括提货申请、采购/销售实提、库存协同、合同结算等模块。

我比较熟悉复杂业务状态流转和数据一致性处理，参与过多主体互转流程改造、提货履约与实提链路通用化改造，也做过接口性能优化、慢 SQL 调优、生产 OOM 排查和财务一致性问题治理。技术栈主要是 Java、Spring Boot、Spring Cloud、MyBatis、MySQL、Redis、RabbitMQ。

我希望继续做 Java 后端方向，偏复杂业务系统、交易履约、性能稳定性和数据一致性这一类工作。
```

## 主钩子：多主体互转

自我介绍里最适合主动递出去的钩子是多主体互转。

推荐表达：

```text
多主体互转项目里，我负责履约板块，通过关系表建模、消息顺序执行和回调主流程复用原履约能力，让原来只支持钢银平台内部交易的链路，可以扩展到钢银与子公司、关联公司之间的主体互转。
```

这个钩子背后要准备的问题：

- 多主体互转的业务背景是什么？
- 为什么会员不直接和主体公司交易？
- 为什么这个能力能降低业务员操作成本？
- 关系表和关系明细表分别记录什么？
- 源订单、目标订单、头节点、中间节点、尾节点怎么定义？
- 主体之间为什么用消息通信？
- 单队列单消费者怎么保证顺序？
- 回调主流程接口怎么复用原履约逻辑？
- 哪些地方必须做特殊判断？
- 提货申请、实提、出库凭证、收货、结算怎么保证链路一致？
- 数据比对 SQL 怎么设计？
- 上线后一个月新增订单 238 笔是怎么统计的？

## 备选钩子：提货履约与实提通用化

如果面试官对多主体互转不感兴趣，可以把话题引到提货履约与实提链路通用化。

推荐表达：

```text
我还参与过提货履约与实提链路通用化改造，主要解决多入口、多业务模式下采购实提、销售实提漏生成或关联错误的问题，尤其是寄售转寄售、多次转卖这类复杂履约链路。
```

这个钩子背后要准备的问题：

- 提货申请、采购实提、销售实提分别是什么？
- 合同资源、库存资源、第三方录入入口有什么差异？
- 为什么多入口容易产生重复分支和漏改？
- 寄售转寄售、多次转卖为什么容易漏生成中间实提？
- 采购/销售关联关系模型怎么设计？
- 如何避免重复生成实提？
- 线上不一致问题怎么发现、怎么修复？
- 新增订单 2159 笔、近一年 627 笔的数据来源是什么？

## 工程能力钩子

如果面试官偏技术，可以在自我介绍后半段补一句工程能力。

推荐表达：

```text
工程稳定性方面，我处理过合同批量打印超时、慢 SQL、生产 OOM 和财务一致性问题，比较习惯从日志、监控、执行计划、线程池、事务和数据对账几个角度定位问题。
```

这个钩子可以引出：

- `CompletableFuture` 并发优化为什么能把 28s 降到 6.71s？
- 自定义线程池参数怎么定？
- `CompletableFuture.get()` 和 `join()` 异常处理有什么区别？
- 93s 慢 SQL 为什么生产和预发执行计划不一致？
- OOM 怎么区分 Java heap OOM、Metaspace OOM、容器 OOMKilled？
- 财务一致性问题里 MVCC 为什么导致重试读到旧版本？
- `REQUIRES_NEW` 为什么能解决重试读旧数据？

## 不推荐的自我介绍方式

不要这样说：

```text
我熟悉 Java、Spring Boot、MyBatis、MySQL、Redis、RabbitMQ，也做过很多项目，比如多主体互转、提货履约、性能优化、OOM 排查。
```

问题是：

- 技术栈太像清单，面试官没有追问方向。
- 项目太多，但没有突出主线。
- 没有说明个人职责。
- 没有把业务复杂度和技术设计连接起来。

也不要把每个项目都展开讲完。自我介绍讲太满，会让面试官觉得没有继续追问的空间。

## 记忆模板

可以按这个模板记：

```text
我是谁：6 年 Java 后端，当前在钢银电商。
业务背景：钢铁 B2B 产业互联网平台，核心交易履约链路。
我的职责：提货申请、实提、库存协同、合同结算、数据一致性。
主项目钩子：多主体互转，关系表建模 + 消息顺序执行 + 回调主流程复用。
补充能力：性能优化、慢 SQL、OOM、财务一致性。
求职方向：Java 后端，复杂业务系统和稳定性建设。
```

最终自我介绍的目标不是证明“我什么都会”，而是让面试官顺着我准备好的项目继续问。
