# GitHub Pages 技术知识库设计

## 目标

建设一个可以公开访问、适合放在简历上的个人技术知识库，重点展示 Java 后端项目经验、问题解决能力和知识领域沉淀。

第一版的目标是“可以放到简历上”，不是一次性迁移完所有语雀内容。

## 目标读者

主要读者包括：

- 面试官：快速了解作者的后端经验、项目复杂度和问题处理能力。
- 技术同事或同行：查看精选项目复盘和技术总结。
- 作者本人：长期维护和沉淀可复用的技术知识。

## 站点定位

站点定位为技术知识库，不是日常随笔博客。

首页需要在 1 到 3 分钟内让读者看出三件事：

- 作者做过真实业务系统。
- 作者能分析复杂后端链路和数据一致性问题。
- 作者有持续总结项目经验和技术知识的习惯。

## 推荐方案

采用 VitePress + GitHub Pages。

选择原因：

- VitePress 适合文档型、知识库型内容组织。
- Markdown 写作和从语雀迁移都比较方便。
- GitHub Pages 不需要自己购买或维护服务器。
- GitHub Actions 可以自动构建并发布静态站点。

暂不选择的方案：

- 纯 HTML/CSS/JS：文章数量增加后维护成本高。
- Jekyll：GitHub 原生支持较好，但对现代技术知识库维护体验一般。
- Astro：更适合个人品牌视觉站，但第一版需要更多设计和开发成本。

## 托管方式

源码仓库建议使用 GitHub Pages 个人站点约定：

```text
https://github.com/<github-username>/<github-username>.github.io
```

发布后的访问地址：

```text
https://<github-username>.github.io
```

发布流程：

```text
本地写 Markdown
-> commit
-> push 到 GitHub
-> GitHub Actions 构建 VitePress
-> GitHub Pages 发布静态站点
```

第一版不需要后端服务、数据库、登录权限和评论系统。

## 首页内容

首页保持清晰、专业、实用，不做花哨的营销式页面。

首页包含：

- 一句简短的职业定位。
- 核心能力关键词：业务建模、链路分析、数据对账、中间件实践、工程质量。
- 精选项目经验入口。
- 知识领域入口。
- 最近更新。
- 关于我入口。

即使第一版公开文章不多，也不能让站点看起来像空模板。

## 文章模板

### 项目经验类

```markdown
# 标题

## 背景
这个项目或模块解决什么业务问题。

## 我的职责
我负责了哪些模块、接口、流程或问题。

## 难点
复杂点在哪里，例如链路长、状态多、数据一致性、异常补偿、性能压力。

## 方案
系统如何设计，关键流程是什么，为什么这样做。

## 结果
交付了什么，解决了什么风险，带来了什么改进。

## 复盘
这个项目沉淀了什么经验。
```

### 问题排查类

```markdown
# 标题

## 现象
问题怎么暴露，影响范围是什么。

## 排查过程
看了哪些日志、SQL、链路、代码或数据。

## 根因
最终确认的问题原因。

## 修复方案
怎么修复，为什么这样修复。

## 验证方式
如何确认问题解决。

## 经验沉淀
以后如何预防类似问题。
```

### 知识总结类

```markdown
# 标题

## 使用场景
这个知识点通常解决什么问题。

## 核心概念
必须理解的概念。

## 实践经验
项目中怎么用，容易踩什么坑。

## 常见问题
常见错误和排查方式。

## 总结
```

## 语雀迁移策略

采用两阶段迁移。

第一阶段：先搭建并发布一个完整、可展示的知识库骨架。

- 搭建站点结构。
- 完成首页和关于我。
- 完成项目经验和问题排查总览。
- 先公开 3 到 5 篇适合展示的精选文章或初版文章。

第二阶段：从语雀逐篇迁移和重写。

- 把语雀当作私有素材库。
- 不直接公开原始笔记。
- 每次选择一篇内容，重写成适合公开展示的文章。
- 删除或泛化公司敏感信息、客户信息、内部域名、账号凭证、真实业务数据和未公开业务规则。

## 第一版内容范围

第一版包含：

- 首页。
- 关于我。
- 项目经验总览。
- 问题排查总览。
- 3 到 5 个知识领域总览页。
- 3 到 5 篇精选文章。

推荐第一批文章方向：

- 复杂业务链路设计与排查经验。
- 业务路由系统实践。
- 数据一致性或对账类问题排查。
- Spring 事务失效场景总结。
- 业务数据对账与修复经验。
- 代码评审与验证闭环。

## 验收标准

首页：

- 能明确看出作者的 Java 后端方向。
- 能突出项目经验和问题排查能力。
- 能进入项目经验、问题排查、知识领域和关于我。
- 不像空模板或半成品。

文章：

- 标题明确。
- 背景和问题具体。
- 方案能体现判断和处理过程，不只是结论。
- 不暴露公司、客户或内部系统敏感信息。

部署：

- GitHub Pages 可以公开访问。
- 导航正常。
- 刷新页面不 404。
- 桌面端和移动端都可读。
- 简历链接无需登录即可打开。

## 第一版非目标

- 不做自定义后端。
- 不接数据库。
- 不做登录或私有文章权限。
- 不做评论系统。
- 不批量公开导入语雀原始笔记。
- 不在知识结构可用之前投入过多个人品牌视觉设计。
