# 项目与问题排查

这里把项目经验和问题排查放在一起，避免真实业务链路被拆散。

项目经验通常回答“这个系统为什么这样设计”，问题排查通常回答“这个系统出问题时怎么定位”。这两类内容放在同一个模块里，更适合按业务链路和真实问题回看。

## 后续整理方向

- 业务链路设计：背景、职责、难点、方案、结果、复盘。
- 线上问题排查：现象、影响范围、排查过程、根因、修复、验证。
- 数据一致性：链路对账、异常补偿、幂等、状态流转。
- 性能与稳定性：慢接口、慢 SQL、线程池、连接池、限流和降级。
